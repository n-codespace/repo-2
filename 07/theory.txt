================================================================================
ASSIGNMENT 07: CONTAINERIZE A PYTHON/FLASK APPLICATION AND BUILD THE IMAGE
================================================================================

1. AIM / OBJECTIVE:
To containerize a Python/Flask web application using a Dockerfile, build a custom Docker image, run it as an isolated container, and test HTTP endpoints.

2. WHAT IS A DOCKERFILE?
A Dockerfile is a plain text file containing a sequence of instructions used by the Docker daemon to assemble a container image automatically.

3. LINE-BY-LINE DOCKERFILE DIRECTIVES EXPLAINED:
- `FROM python:3.9-slim`:
  Specifies the parent base image. Using `slim` provides a minimal Linux OS with Python pre-installed, keeping image size small and secure.
- `WORKDIR /app`:
  Sets the active working directory inside the container for subsequent commands (`COPY`, `RUN`, `CMD`).
- `COPY requirements.txt .`:
  Copies only the requirements file first. If application code changes later, Docker reuses the cached layer of installed packages instead of reinstalling them.
- `RUN pip install --no-cache-dir -r requirements.txt`:
  Executes the package installer inside the image during build time.
- `COPY . .`:
  Copies the rest of the application source code into `/app`.
- `EXPOSE 5000`:
  Documents the network port the container listens on at runtime.
- `CMD ["python", "app.py"]`:
  Provides defaults for an executing container. Starts the Python Flask web application when container launches.

4. STEP-BY-STEP BUILD & RUN PROCEDURE:
Step 1: Build the Docker Image:
        docker build -t flask-docker-app:v1 .
        (-t tags the image with a name and version; the trailing dot indicates current directory).

Step 2: Verify the Built Image:
        docker images
        (Confirm that 'flask-docker-app' appears in the list).

Step 3: Run the Container:
        docker run -d --name flask-live-container -p 5000:5000 flask-docker-app:v1
        (-d runs in background; -p 5000:5000 maps host port 5000 to container port 5000).

Step 4: Access and Test:
        Open web browser: http://localhost:5000/
        Or use curl: curl http://localhost:5000/health
        Response: {"hostname": "...", "status": "healthy", ...}

Step 5: View Logs:
        docker logs -f flask-live-container

Step 6: Stop & Cleanup:
        docker stop flask-live-container
        docker rm flask-live-container

5. CONCLUSION:
Containerizing the Python Flask application ensures environment parity: the application runs identically on local developer laptops, staging servers, and production cloud infrastructure.
